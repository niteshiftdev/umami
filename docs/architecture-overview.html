System Map

Umami is a Next.js analytics app with a dual-mode event store.

The same app serves the dashboard, JSON API, collection endpoint, link redirects, pixel GIFs, and tracking script. Postgres/Prisma is the default system of record; ClickHouse and Kafka can take over high-volume event ingestion while Prisma keeps account metadata.

Runtime Switches

Environment variables that materially change architecture.

Switch Effect Code area
DATABASE_URL Required Postgres connection for Prisma and migrations. src/lib/prisma.ts, prisma/schema.prisma
DATABASE_REPLICA_URL Adds Prisma read-replica extension for raw query reads. src/lib/prisma.ts
CLICKHOUSE_URL Switches analytic reads/writes to ClickHouse implementations where available. src/lib/db.ts, src/lib/clickhouse.ts
KAFKA_URL + KAFKA_BROKER Sends event messages to Kafka topic event instead of direct ClickHouse insert. src/lib/kafka.ts, saveEvent.ts
REDIS_URL Enables auth-key storage and cached link/pixel slug lookups. src/lib/redis.ts, collect routes
COLLECT_API_ENDPOINT Rewrites an alternate public collection path to /api/send. next.config.ts, tracker build
TRACKER_SCRIPT_NAME Publishes additional script aliases that rewrite to /script.js. next.config.ts
DISABLE_AUTH Returns the built-in admin user from auth checks when enabled. src/lib/auth.ts

Operational Shape

Default deployment and scale-out path.

01
Small/default install
Next.js server plus Postgres. Prisma owns metadata and analytics rows; Docker Compose provisions both services.
02
Read-heavy dashboard
Add DATABASE_REPLICA_URL so Prisma raw query reads can use a replica while writes stay primary.
03
High-volume analytics
Enable ClickHouse; event writes and report reads use ClickHouse-specific SQL helpers and schema.
04
Buffered ingestion
Enable Kafka in front of ClickHouse for event messages; Redis can cache auth and slug lookups.
